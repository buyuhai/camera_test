# Design

## Context

检测半径的外沿微调已在 `443c86e` 落地：`hough_gui/core/detector.py` 在 Hough 初值上搜索圆心 ±5 像素、半径 0.85–1.25 倍的同心圆，取圆周梯度均值最大的组合。基线规格 `circle-detection` 目前只描述参数、非法输入、结果表示与颜色空间，没有描述该行为；真实图片的验收参数与结果也没有入库存档。

仓库现有的二进制图片策略是「测试图不入库」。本次需要把两张标注结果图嵌入 README，因此必须为验收证据开一个受控例外，同时避免把临时样图、导出结果整体放进版本库。

## Goals / Non-Goals

**Goals:**

- 把外沿贴合行为写成可验收的规格，并给出硬币/盘子两组可复现参数。
- 让验收结果（圆数量、圆心、半径、结果图）在仓库内可查、与 README 一致。
- 根目录只保留工程文件；样图、证据图各归其位。

**Non-Goals:**

- 不修改检测算法或参数默认值。
- 不引入批量处理、预设保存或自动验收脚本。
- 不把原始测试图片纳入版本库。

## Decisions

### 沿用现有梯度微调，不新增运行时代码

`443c86e` 已实现外沿微调，本次只把行为补进 `circle-detection` 规格并验收。备选是重新设计半径拟合（例如椭圆拟合或亚像素边缘），会扩大范围且没有需求支撑，未采用。

### 两张图各自给参数，不追求单一参数集

盘子 `minRadius=200` 用来排除背景高对比假圆，硬币 `minRadius=120` 用来保留半径约 180 像素的外圈；硬币 `param2=150` 抑制内部人像/花环纹理，盘子 `param2=60` 已足够。两组参数在各自图片上实测稳定，共用一组会在其中一张图上漏检或误检，因此按图给出验收参数。

### 证据图入库，源图留在 `samples/`

- `docs/acceptance/plate_result.png`、`docs/acceptance/coins_result.png` 入库，README 用相对路径引用，克隆后可直接渲染。
- 原始图片移入 `samples/plate.png`、`samples/coins.jpg`，继续由 `.gitignore` 排除，避免把用户样图当作产品资产。
- `.gitignore` 只对 `docs/acceptance/` 放行，`samples/`、`out/` 与临时导出仍不入库。
- 备选：源图与结果图全部入库——可完全复现，但仓库体积翻倍且违背既有策略；备选：结果图也不入库——README 无法直接展示验收证据，不满足本次要求。

### 验收记录放在变更内

除 `tasks.md` 的勾选进度外，增加 `acceptance.md` 记录环境、输入尺寸、参数、结果与复核命令。归档后该文件与 proposal/specs/design/tasks 一起构成「规格确认 → 实施进度 → 验收结果」的完整链路。

### README 以「启动方式 + 验收参数」组织

启动命令集中在「启动方式」；验收参数与结果放在独立章节，按盘子/硬币分表，并嵌入两张结果图。目录结构和纳入/不纳入清单同步更新，避免文档与仓库实际内容不一致。

## Risks / Trade-offs

- **结果图与算法脱节** → 结果图是某一提交的验收快照；算法再变化时应在新的 change 中重新生成并在 acceptance 记录中注明提交号。
- **二进制证据增加仓库体积** → 仅两张、合计约 1 MB，且限定在 `docs/acceptance/`；其余图片继续排除。
- **验收参数过拟合单张图片** → 规格只锁「外沿半径误差 ≤ 2 像素、数量正确」的可见行为，参数作为验收输入记录；算法实现仍可替换。
- **样图移动后旧路径失效** → README、acceptance 记录统一使用 `samples/plate.png`、`samples/coins.jpg` 新路径，并说明这两张图仅本地保留。
